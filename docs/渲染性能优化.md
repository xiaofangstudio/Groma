# 渲染性能优化（第一轮）

日期：2026-11-22
范围：画布绘制、平移、高 DPI、图层树首屏。目标不是“跑分好看”，而是拖拽、平移、缩放时先不卡。

## 这一轮改了什么

### 1. 交互时降级细节

`src/render/draw.ts` 增加 `DrawOptions`：

- 拖动、缩放、画新对象时 `interactive=true`。
- 交互中跳过画板阴影、画板名称标签和点阵网格。
- 松手后自动回到完整细节，不需要手动刷新。

画板阴影每帧 `shadowBlur=18`，是 Canvas 2D 最贵的绘制之一。交互时先把它拿掉，松手再补回来。

### 2. 画布像素预算

`src/ui/CanvasView.tsx` 的 `pickDpr()`：

```text
dpr = min(系统 DPR, 2, sqrt(8,000,000 / (宽 × 高)))
```

- 最多 800 万物理像素，避免 4K / 150% 缩放下 canvas 缓冲区过大。
- DPR 上限 2，超过 2 的收益远小于显存与填充成本。
- 2D 上下文改为 `{ alpha:false, desynchronized:true }`，减少合成与同步开销。

### 3. 平移用快照缓存

旧逻辑：每个 `pointermove` 都把整个场景重画一遍。
新逻辑：

- 按下平移时，把画布内容区裁成一张位图缓存。
- 移动时只把缓存位图按位移画回去，再重画标尺。
- 用 `requestAnimationFrame` 合并同一帧内的多次移动。
- 松手时才把最终 viewport 一次性写回 store。
- 平移中忽略滚轮，避免和缩放打架。

缓存只在平移期间存在，结束或取消立即释放。

### 4. 移除常驻模糊

`.canvas-tip` 原来的 `backdrop-filter: blur(4px)` 会一直让 GPU 合成一层模糊。已改成不透明度更高的纯色底，画布上方不再常驻模糊层。

### 5. 滚轮缩放合并到帧

旧逻辑：每个 `wheel` 事件立即提交一次 zoom，并触发一次全场景重绘。
新逻辑：

- `wheel` 事件只累积 `deltaY`，同一帧内最多提交一次缩放。
- 缩放期间进入低细节模式，停手 180ms 后恢复画板阴影、名称标签与点阵网格。
- 平移进行中忽略滚轮，避免平移和缩放打架。

### 6. 图层树默认折叠

旧图层面板会把整棵树一次性铺开：5000 个节点就是 5000 行 React。
现在：

- 每行有展开 / 折叠箭头，默认只画顶层画板。
- 选中画布里的深层节点时，自动展开它到当前页面的那一条路径。
- 叶子节点不显示空箭头，缩进按层数计算。

这一刀不是为了“好看”，是为了打开大工程时左栏不先卡死。

## 实测结果

### 门禁

- `npx tsc --noEmit`：通过。
- `npm run gate`：10 个测试文件、34 条测试全绿，GATE PASS。
- 新 EXE：`src-tauri/target/release/groma.exe`，3,203 KB，2026-11-22 08:39:21。
- MCP 自检：通过，`selftest ok`。

### 5000 节点真实工程

`tools/make-perf-project.mjs` 生成 `Perf-5000.groma`：

- 50 个画板 × 100 个子节点，共 5,050 个图层。
- 真实 EXE 打开：左栏只画 50 个顶层画板行，状态栏显示 5050 图层。
- 手形工具平移：视口、标尺、内容一起移动，没有白屏、假死或画板位置被误改。
- 这仍然不能证明 60fps，只能证明这一版在 5000 节点下能打开、能平移、图层树首屏不爆炸。

### 5000 节点绘制基准

`src/bench/render.bench.test.ts`：

- 场景：50 个画板 × 100 个子节点，约 5,050 个绘制节点。
- 视口：1420 × 880。
- mock canvas context，只测 JS 绘制调用，不代表 GPU 光栅。
- 完整模式：画板阴影 50 次，节点全部遍历。
- 交互模式：阴影 0 次，名称标签与点阵网格跳过。
- 放大视图：裁剪掉 300+ 节点。
- 单跑平均约 **1.55ms/帧**；全量 gate 并行跑时约 **2.88–3.26ms/帧**。

这不是“5000 节点 60fps 已达标”的证据。它只能说明：绘制遍历本身没有爆炸；真实帧率还要在真实 canvas + GPU 上用 5000 节点工程滚动实测。

## 仍然没做

- 真实帧时间 HUD，能在窗口里看到每帧耗时。
- 图层面板虚拟滚动（折叠后首屏已够用，展开超大画板仍需）。
- 画板阴影缓存。
- 静止场景缓存与选择层分离（当前选图层仍会重画整张场景）。

## 下一轮优先级

1. 真实窗口跑 5000 节点工程，记录拖拽 / 平移 / 缩放的帧时间，先把“卡不卡”变成数字。
2. 场景与选择分离：选图层、选框只重画覆盖层，不重画整张画布。
3. 图层面板虚拟滚动，展开 5000 节点也只为可见行建 DOM。
4. 画板阴影缓存，静止状态不再每帧重算 `shadowBlur`。
