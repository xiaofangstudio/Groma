# Groma UI 家族化改版记录

初版：2026-11-22 07:26（Asia/Shanghai）｜ 最近更新：2026-11-28（Figma 式布尔组：可展开、可切换、可拍平/解散，296 tests）

## P0 Figma 式布尔组：源层保留、可展开编辑、随时切换运算（2026-11-28 22:50）

**为什么做**

上一刀只解决了“布尔入口看得见”，点完仍是单个扁平 `path`，源对象被吃掉；改并集/差集只能撤销重来，图层树也展不开。Figma 的布尔不是一个结果图层，而是一个持续可编辑的布尔组。用户要求“和真的 Figma 功能一模一样，用着完全没区别”，所以这一刀把布尔从一次性运算改成真正的组。

**改法**

- `SceneNode` 新增 `type:'boolean'` 与 `booleanOp`。布尔组自身保存合并后的缓存 `pathData/pathContours/fillRule`，同时保留全部源图层作为子层；画布只画缓存，子层不重复绘制。
- 多选执行并集 / 差集 / 交集 / 排除后生成布尔组，源层按原 z 顺序成为子层，世界位置不变；不再是“合成 1 个扁平图层”。
- 图层树布尔组带展开箭头，可展开到源形状；右键提供“解散布尔组 / 拍平为路径”。
- 单选布尔组时，底部条从“合成”切换为“布尔类型”，四个操作直接切换当前组的运算并即时重算；顶栏“布尔”菜单、右栏“布尔类型”分段控件同源。
- 子层移动、改尺寸、删除、重排、换父级后统一重算布尔缓存；嵌套布尔组按深度从深到浅刷新，缓存原点变化时反向补偿子层坐标，避免结果漂移。
- 布尔组 W/H 缩放会同步缩放全部子形状，保持当前运算；命中测试改用合并路径而非整块包围盒，减集形成的洞与子形状溢出区域不再误选布尔组。
- 拍平只删除布尔组子树并留下单条钢笔路径；解散把子层按世界坐标放回父级。两者都可一步撤销。

**验证**

- `npm run gate`：44 文件 / **296 tests** 全绿；`tsc`、Vite、MCP 自检、Tauri EXE 全部通过。
- 真实 EXE `布尔组验收.groma`：多选“红块 + 蓝块”点差集，生成“差集 1”，右栏类型“布尔组”；展开后图层树出现“蓝块 / 红块”；W 从 220 改到 330，布尔形状与子形状同步横向缩放；点并集后底栏与右栏同时高亮并集，结果宽度变为 340；拍平得到“拍平 1”、无子层；撤销恢复“差集 1”和两个子层。
- 截图 `shots/boolean-group.png`（差集布尔组与展开子层）、`shots/boolean-resized.png`（W=330 等比缩放）、`shots/boolean-union.png`（切换并集）、`shots/boolean-flattened.png`（拍平后单路径）。

**指纹与边界**

- EXE **3,436,032 B（3,356 KB，2026-11-28 22:46:53）**；CSS `index-CibxLhyv.css` 90.42 kB、JS `index-Di0a1xkB.js` 689.56 kB。
- 仍只允许同父级的矩形、椭圆、闭合钢笔和布尔组参与运算；文本、图片、普通容器、箭头不接收。
- 布尔组旋转目前只作用于缓存路径，旋转后继续编辑子层的局部坐标还没有按旋转矩阵转换；布尔组作为蒙版、自动布局子项也尚未专项验收。

## P0 布尔运算可见入口：多选底部快捷条、右键同项、顶栏改称布尔（2026-11-28 21:42）

**为什么做**

布尔运算底层早就有 `union / subtract / intersect / exclude`，但入口藏在顶栏“矢量 ▾”菜单里；多选两个图形后，画布上没有任何直接提示，用户只看到两个选中框，很容易以为 Groma 没有布尔。用户提出“底下有搞个布尔图什么的吗、布尔运算整合成一个”，本质仍是可见入口问题：能做，但要一眼能找到，并且点完确实收成一个图层。

**改法**

- 画布底部新增随多选出现的布尔快捷条：并集 / 差集 / 交集 / 排除四个带自绘轮廓图标的按钮，右侧固定说明“合成 1 个图层”；只在至少两个同父级闭合矢量对象可布尔时出现，不常驻、不占顶栏。
- 点击后直接调用现有矢量运算并收成单个 `path` 图层，画布 Toast 明确写“并集完成 · 已整合成 1 个图层”这类结果，不再只有菜单里悄悄变化。
- 顶栏矢量按钮标签随选择变化：两个以上对象满足布尔时显示“布尔”，其余时候仍显示“矢量”；“矢量 ▾”菜单保留分割 / 拍平 / 描边，不重复塞进底部条。
- 画布右键菜单新增“布尔运算 · 合成 1 个图层”分组，四个操作与底部条同源；多选后不必离开画布去顶栏找。
- 布尔条激活时左下角提示上移 46px，避免和底部条互相压住；选中结果变成单层后底部条自动收起，撤销回多选后自动恢复。

**验证**

- `npm run gate`：44 文件 / **289 tests** 全绿；`tsc`、Vite、MCP 自检、Tauri EXE 全部通过。
- 真实 EXE `交互入口验收.groma`：Shift 追加选中“太阳 + 玻璃卡”后，底部条文字“布尔 并集 差集 交集 排除 · 合成 1 个图层”，顶栏按钮变“布尔”；点“差集”后图层树从 8 层变 7 层，选中项只剩“差集 1”，画布上玻璃卡出现太阳形状的圆洞，Toast“差集完成 · 已整合成 1 个图层”；撤销后恢复“太阳 + 玻璃卡”两层、底部条重新出现。
- 截图 `shots/boolean-bar.png`（多选底部条 + 顶栏“布尔”）、`shots/boolean-result.png`（差集合成单层与圆洞结果）。

**指纹与边界**

- EXE **3,433,984 B（3,354 KB，2026-11-28 21:42:22）**；CSS `index-CKuWlfxa.css` 89.72 kB、JS `index-BXxM91c9.js` 680.63 kB。

## P0 渐变画布编辑：端点改角度、线外环移位置、色标沿线拖（2026-11-28 20:54）

**为什么做**

渐变此前只有右栏能改：线性渐变只有一个角度数字框，画布上没有任何手柄，用户无法直接拖角度；径向渐变虽有圆心/半径，但线性渐变整层等于“代码里有、画布上无入口”。用户明确点出：渐变不能拖位置、首先不能改角度，这是最重要的。

**改法**

- 画布手柄从“只认径向”改成“取当前图层最上层可见渐变”，线性和径向共用一套选中即出现的覆盖层。
- 线性渐变画布覆盖层：两端实心圆点、线上方偏置空心圆环 + 短虚线连回线中点、线上中间色标圆点；颜色取对应色标色值。
- 拖两端圆点改角度与长度；另一端保持不动，按住 `Shift` 按 15° 吸附。
- 拖线上方偏置空心圆环整条平移，方向、长度、色标全部保持；不再只能靠数字“反向”或角度框。
- 拖中间色标圆点沿渐变线改 `offset`，右栏“位置%”同帧回写；色标拖到 0–1 之外会夹住。
- 手柄几何按节点自身旋转做局部坐标 ↔ 屏幕坐标换算；旋转后的图层，渐变线不会漂到错误位置。
- 径向渐变沿用圆心/半径手柄，同时修正旋转映射；右栏补两行画布操作提示，明确“拖哪里、Shift 怎么吸附”。

**验证**

- `npm run gate`：44 文件 / **289 tests** 全绿；`tsc`、Vite、MCP 自检、Tauri EXE 全部通过。
- 真实 EXE 线性验收工程 `渐变手柄验收.groma`（天空渐变改为 3 色标线性）：角度 `0 → 344.8`；端点上移后坐标从 `(1157.2,525)` 到 `(1087.1,375)`；拖线上方移动环后整条线 `+55,+28`、角度仍 `344.8`；中间色标 `55% → 76%`。
- 径向验收（太阳）：圆心屏幕坐标 `(845.5,386.7) → (877.5,406.7)`，半径 `74 → 105.9`，右栏 X/Y/R 同步为 `87.2 / 76.2 / 105.9`。
- 截图 `shots/gradient-handles.png`：线性渐变线、两端点、中点移动柄、色标、右栏角度与提示同屏。
- 构建指纹：EXE **3,433,472 B（3,353 KB，2026-11-28 20:54:27）**；CSS `index-BvLQhksp.css` 88.52 kB、JS `index-EPctUjcU.js` 678.65 kB。

**边界**

- 画布只操作当前图层最上层可见渐变；右栏切换到第 2 层填充时，画布手柄仍停在第 1 层，多层渐变联动尚未接。
- 线性渐变暂未加图案填充、角度刻度环、独立渐变条；色标拖动不重新排序，越过相邻色标后视觉按 offset 排序，但列表顺序可能暂时不同。
- 渐变位置只通过画布线上方偏置圆环移动，没有线性 X/Y 数字字段；Figma 同样以画布拖拽为主。

## P0 可见入口：层级、图层拖拽、参考线开关、单选对齐（2026-11-28 19:53）

**为什么做**

有一批能力其实已经在代码里，却只能靠快捷键或记住右键：置顶/置底只有 `Ctrl+Shift+]`，没有单步上移/下移；图层树能点选但不能拖动改序或换父级；参考线画出来以后不能隐藏、不能锁，误拖就丢。这等于“功能存在但入口不存在”，和 Figma 的日常手感对不上。

**改法**

- 右栏顶部加常驻“层级”条：置底 / 下移 / 上移 / 置顶。按当前父级判断边界并禁用无效方向；多选时整批进退，且只进一条撤销。
- `Ctrl+]` / `Ctrl+[` 补单步上移/下移；`Ctrl+Shift+]` / `Ctrl+Shift+[` 仍为置顶/置底；画布右键菜单补四项层级命令和快捷键。
- 图层行右键菜单：复制、四级层级、成组/解散、隐藏/锁定、删除；不复用页面菜单，不影响页面操作。
- 图层树拖拽：悬停行的上/下缘出现插入线，拖到画板/分组/区块中间则成为其子层；跨父级时保持世界坐标不变，整棵子树随行，一次撤销。顶层 Frame 也能改序，不再被页面根拦住。
- 左栏图层树改为顶层在上显示，和画布 z 序一致；“上移”在列表里真的往上走。
- 参考线状态：底部状态栏在页内有参考线时显示条数、眼睛、锁。隐藏后参考线不画也不参与吸附；锁定后仍显示和吸附，但不能拖动或删除。
- 图层顺序改为顶层在上后，页面树里的容器展开、图层计数、右键选择仍沿用原节点 id，不影响页面排序。
- 单选右栏“对齐与变换”补 6 向对齐：左/水平居中/右/顶部/垂直居中/底部，相对直接父画板、分组或区块；父级是页面时按钮禁用，不再出现点了没反应的假入口。多选仍按选区外接框对齐。

**验证**

- `npm run gate`：44 文件 / 286 tests 全绿；`npx tsc --noEmit`、前端构建、MCP 自检、EXE 编译通过。
- 真实 EXE `交互入口验收.groma`：参考线 2 条，隐藏后 `.manual-guide` 2→0，恢复 2；锁定按钮变 `is-on`，参考线仍 2。
- 图层树展开：`["天气图标","温度","云","云","云","太阳","玻璃卡","天空渐变"]`；选最底层“天空渐变”，层级条只有上移/置顶可用，点上移后顺序变 `[…太阳,天空渐变,玻璃卡]`。
- 拖拽“玻璃卡”到顶层“天气图标”上方：落点后顺序 `["玻璃卡","天气图标","温度","云","云","云","太阳","天空渐变"]`，父级从画板改为页面根，世界位置未跳。
- 图层右键菜单 8 项齐全；单选对齐 6 个按钮全可用，天空渐变右对齐后 X 从 96→192。
- 构建指纹：EXE 3,431,936 B（3,352 KB，2026-11-28 19:53:42）；CSS `index-p4n8iCJ9.css` 88.09 kB、JS `index-DbLD_Ru2.js` 674.74 kB。

**边界**

- 拖拽一次只搬当前行，不搬多选整组；跨页面拖拽未开。
- 图层树右键没有重命名，重命名仍走右栏名称字段；这是为避免和页面重命名输入框抢状态。
- 参考线隐藏/锁定是视图状态，不进工程、不持久化；工程内参考线坐标仍保存。
- 跨父级进入 Auto Layout 容器会按布局重新排，不保留手工坐标。

## P0 画布基础手感：Shift 约束、框选与布尔、顶栏减法、演示主题、渐变与效果（2026-11-28）

**为什么做**

拿天气图标教程复刻时，卡点几乎全在基础交互：椭圆拖不出正圆，拖拽先出现一个方框再变形状；框选不动，布尔藏在“更多”里，还因为误选父画板整排禁用；演示打开是黑框黑卡，像套壳 Demo；圆角、可拖的径向渐变、背景模糊、内阴影都找不到入口。这不是缺功能，是 Figma 的手感没对上。

**改法**

- 绘制加 Shift 约束：矩形/椭圆/画板/区块/多边形/星形按住 Shift 收成正方形或正圆，以按下点为锚、取较长边为边长；直线/箭头按 45° 步进锁方向。
- 拖拽预览改成真实形状：椭圆直接画椭圆，多边形/星形用实际路径，矩形/画板画矩形描边，不再先给一个虚线方框。
- 容器内的框选：在画板/分组空白处按下先不移动容器，拖动超过 4px 出框选并选内部子层，原地松手才选容器；Shift 可追加框选与点选。
- 框选修复：部分相交的容器不再整块塞进选区，避免选两个图形时把画板一起选中、导致布尔全禁用。
- 顶栏分组：常驻 3 个主组——移动（含抓手）、画板（含区块/切片）、形状（矩形/直线/箭头/椭圆/多边形/星形），加文字、钢笔；带下拉的按钮右侧都有独立小三角，主按钮单击直接用当前工具，点三角才展开菜单；“矢量 ▾”也补上可见三角，不可用项显示原因。
- 右栏“对齐与变换”补旋转与圆角快速字段；画布选中框加旋转手柄，Shift 按 15° 步进；Shift 移动锁单轴，Shift 缩放锁宽高比。
- 智能参考线补极值/圆心标记：吸附线仍是横平竖直红实线，目标图层的边、中心、圆的上下极值交点画小圆点，中心点用空心环。
- 径向渐变上画布：选中带径向填充的图层，画圆心手柄与半径手柄，拖圆心改位置、拖外圈改半径，虚线辐条连接，走撤销。
- 效果补内阴影与背景模糊；背景模糊在绘制前截取身后画布按轮廓裁剪再模糊，内阴影只在图层内部成暗边。右栏四类效果并排为两列添加。
- 演示主题换成 Groma 纸感：暖黑半透明背景、白卡片、米色顶栏、网格纸舞台；竖版画板套白色设备边和圆角；热区改品牌黄，提示改“黄色虚线热区”。

**验证**

- `npx tsc --noEmit` 通过；`snapping / geometry / boolean` 26 tests 通过（snapping 10 条含极值/中心标记）。
- 真实 EXE：顶栏为移动/画板/形状 3 组，三角均 8×5 px；形状菜单 6 项，选椭圆后主按钮图标与 aria-label 立即变椭圆；空白工程框选两个矩形 `selected=["矩形1","矩形2"]`、布尔六项全部可用，点并集得到“并集 1”钢笔结果；椭圆在明显非正方手势下仍得到 `W=91,H=91`；旋转手柄 Shift 拖到右侧读 90；天空圆角读 44；径向圆心 `cx 561.5→598.04`；玻璃卡三张效果卡；演示 `cardBg rgb(255,255,255)`、手机预览 `isDevice=true / 26px`。
- 构建指纹：EXE 3,429,888 B（3,350 KB，2026-11-28 18:44:54）；CSS `index-QAGvVUJ6.css` 84.54 kB、JS `index-BrL5Snww.js` 647.37 kB。

**边界**

- SVG 导出目前只带投影与整层模糊，内阴影/背景模糊进 PNG 与画布；导出前不能对外宣称四类效果全格式一致。
- 旋转后的缩放仍按未旋转矩形算宽高，极端角度会偏；旋转后的绝对包围盒也还没改。
- 多径向填充时画布手柄取第一个可见 radial，右栏默认第 0 层，多层径向尚未同步同一层。
- 手机设备边是白色 7px 环 + 26px 圆角，没有刘海/状态栏/侧键，是否做完整机身待定。

## P0 欢迎页最近工程移除与自定义右键（2026-11-28）

**为什么做**

欢迎页的最近工程只能打开，不能清理：误建的工程、重复的“未命名设计”会一直堆在列表里。卡片右键还是 WebView2 默认菜单（返回/刷新/打印），鼠标停在任意位置右键都像网页，不像桌面工具。欢迎页是每天第一眼看到的地方，这两处不修，整个产品的地基感就立不住。

**改法**

## P0 生产闭环第一刀：组件实时联动 + 自动布局生命周期（2026-11-28）

**为什么做**

上一刀把 Auto Layout 的尺寸规则补对了，但真实设计时仍要停下来迁就工具：改主组件后实例不会动，得手动“同步全部”；往自动布局里加一层、删一层、复制一层后布局停在原地，得点“重排”。这两处不闭合，设计系统一改就散，日常排版每加一层都在返工。

**改法**

- 组件实时联动：找到被编辑节点所属的最近主组件，编辑主组件或其子层后，自动重建该主组件的所有实例；实例自身的文字/填充/尺寸等覆盖继续按路径重放，不丢。
- 编辑实例内部不会被误判成主组件改动，避免把实例改动反灌回主组件。
- 右栏改属性走 `applyPatch`，主组件编辑 + 实例同步合并成一条 `doc` 撤销；画布拖动走事务，事务结束同样自动同步，并把整次拖动与实例重建合成一条撤销。
- 自动布局生命周期：插入、删除、恢复、复制子层都立即重排，不再依赖“重排”按钮；容器 Hug 时新增子层会直接撑开，删除/撤销会缩回。
- 单个失效实例同步失败只跳过该实例，不影响其它实例与主组件编辑。

**验证**

- `npm run gate` PASS：44 文件 / 283 tests；`autoLayout.test.ts` 增至 12 条（新增插入/删除/恢复自动重排），`instance.test.ts` 8 条（主组件子层联动 + 覆盖保留 + 实例内部不误判），`editor.test.ts` 45 条（主组件改动同步实例并一步撤销）。

## P0 Auto Layout Fill/Fixed/Hug（2026-11-28）

**为什么做**

上一刀自动布局只有方向、间距、内边距和“适应主轴”，子层只能固定宽度；一遇到按钮组、侧栏、卡片列表这种“谁吃剩余空间、谁按内容收缩”的真实布局就露馅。Figma 的 Auto Layout 之所以能干活，靠的就是主轴 Fill、交叉轴 Fill、容器宽高分别 Hug/Fixed 这三组规则闭合。

**改法**

- 数据层新增容器 `hugWidth / hugHeight`，可分别决定宽、高是否包住内容；旧 `hug` 保留为旧工程兼容，读取时按主轴回退。
- 子层新增 `layoutGrow`（主轴 Fill）与 `layoutAlignSelf`（交叉轴对齐覆盖，`stretch` 即交叉轴 Fill）。
- 主轴 Fill 按剩余空间在多个 Fill 子层间平分；固定项保持原宽高，容器 padding 与 gap 先扣除。
- 容器同时开启“适应主轴”时，主轴 Fill 自动失效并回到开启 Fill 前的固定尺寸；交叉轴 Hug 同理，不会因子层曾被拉伸而把容器越撑越大。
- 右侧新增“布局尺寸”段：父级是自动布局时，子层可分别勾选主轴与交叉轴 Fill；容器原“适应主轴”改为“适应宽度 / 适应高度”两个勾选。
- 布局改为最多 4 轮后序遍历：先算子层，外层把内层容器 Fill 拉伸后，下一轮内层再按新尺寸回流，嵌套自动布局不再停在旧宽度。
- 关闭子层 Fill 时恢复开启前的固定尺寸并清掉基准，反复开关不会越开越宽。

**验证**

- `npm run gate` PASS：44 文件 / 280 tests；`autoLayout.test.ts` 从 5 条增至 11 条，新增主轴 Fill、交叉轴 Fill、双轴 Hug、嵌套二次回流、Hug 下回退 Fill 基准、交叉轴 Hug 回退基准。
- 真实 EXE `AutoLayoutUx.groma`：`按钮组` 760×120，按钮 1 横向 Fill 后 W 150→210，关闭后回 150；容器改 H 160 后，按钮 1 纵向 Fill H 64→104；容器“适应宽度”W 760→700，关闭后回 760；最终按钮 1 210×104，其余 150×64，右栏 `overflow: []`；截图 `shots/autolayout-sizing.png`。
- 构建指纹：EXE 3,419,136 B（3,339 KB，2026-11-28 15:51:40）；CSS `index-Bv6obcoY.css` 81.68 kB、JS `index-CLz1V38Y.js` 648.21 kB。

**边界**

- 仍缺换行（wrap）、布局网格、画布直接拖拽子层重排；新增或删除子层后仍要手动点“重排”，未接自动重排。
- 文字节点自身的内容 Hug 尚未做；目前 Hug 只按子层当前尺寸计算。
- 容器 Hug 与子层 Fill 同时开启时，主轴 Fill 不生效并回退到开启前尺寸；这是当前与 Figma 行为最接近的近似，不是完整的最小内容推导。

## 这一轮为什么不是「美化」

Reelix 的失败不是功能少，而是**功能表和用户拿到的产品不是同一个东西**：交付的 exe 比源码旧、按钮没有后端、界面靠堆面板显得专业、图标还是脚手架默认。FloatLab 则是架构野心跑在可用性前面，界面重做被排到三期，长期停在半成品。

Groma 这一轮只做三件事：把首屏变成真正能开始工作的页面，把界面拉回 Strata / Chapter 同族口径，把每个新入口都接到真实行为上。没有新增假按钮。

## A03 Section 基础链路（2026-11-23 19:12）

Section 不是“换皮画板”，是页面下的一层透明容器：有名称、边框、可选填充，不裁剪子图层；子 Frame 可随 Section 移动，导出时只导出区块内容。

- 类型：`NodeType` 增加 `'section'`，schema 同步接受；section 默认无填充、`clipContent=false`；旧工程不受影响，新工程写入 `type:"section"`。
- 创建：顶栏新增“区块工具 S”，画布拖拽创建；单击默认 800×600；图层树显示区块图标，顶层区块可折叠；右栏显示“区块”名称/尺寸/填充/透明度。
- 挂载：`deepestFrameOrSection()` 只在新建画板时允许把 Frame 挂进 Section；普通矩形/椭圆仍只挂画板或页面，避免图形被误塞进区块。Section 本身只从页面根创建，不做无限嵌套。
- 渲染：`drawSection` 画细边框 + 左上角名称 + 可选填充，不裁剪子节点；名称在 `scale < 0.15` 时隐藏，避免 34×22 缩略图被文字糊满。
- 导出：`renderFramePng` 接受 frame 或 section；Section 导出裁到 Section 边界，只画子节点，不画区块标签/边框；`pickFrame` 选中区块时导出整块，选中子 Frame 时仍导出 Frame。
- 删除：整块 Section 删除会连同子 Frame 进入同一条撤销记录；撤销恢复子树（editor 测试覆盖）。

**验收**

## 图片资产层与位图节点（2026-11-24 07:54）

**为什么做**

Figma 基线里的 C06 图片还只有 SVG 内嵌图，没有可独立选中的位图节点：本地 PNG/JPG 进不来，工程 `assets` 只是空的占位目录。先把「图片进得来、能改、能存、能导出」这一垂直切片做通，后面 Strata 位图回传、Vexa 工程往返和选区外部处理才有落点。工程级导入仍只留入口，这轮不碰。

**改法**

- 数据模型：`NodeType` 增加 `image`；`SceneNode` 增加 `assetId`；新增 `ImageAsset { id, name, mime, file, w, h, bytes }` 与 `GromaDoc.assets`；`scene.json` 只存资产引用，图片本体在 `<工程>/assets`。
- 校验：`schema.ts` 只接受 `image/png`、`image/jpeg`、`image/webp`；资产路径必须是 `assets/<文件名>`，拒绝 `..`、反斜杠和越界路径；图片节点缺 `assetId` 或引用不存在直接拒绝工程。
- Rust：新增 `groma_write_asset` / `groma_read_asset`，校验扩展名、MIME、PNG/JPEG/WebP 文件头与 64MB 上限，重名自动编号；读回统一转 data URL。
- 前端缓存：`src/io/images.ts` 按 `asset.id` 缓存图片位图与 data URL，打开工程/新建工程触发 hydrate；画布与页缩略图订阅加载完成重绘，缺图显示占位不崩。
- 导入：顶栏“导入”接受 `.svg/.png/.jpg/.jpeg/.webp`；位图按自然尺寸插入，并限制到父容器 80%，优先挂当前选中画板/区块，否则落到视口中心画板，保证默认导出画板能带上图片。
- 检查器：右侧显示文件名、原始尺寸、文件大小、X/Y/W/H、圆角、透明度与“恢复原比例”；“替换图片”用隐藏文件输入换图，保留节点位置与尺寸，默认图层名随新文件更新，自定义图层名保留；图层树和类型标签显示“图片”。
- 渲染/导出：`drawImageNode` 支持圆角裁切、透明度、缺图占位；SVG 导出内嵌 `data:image/...;base64`，有圆角时套 `clipPath`；PNG/JPG 导出前预载资产。
- 紧凑窗口：`@media (max-height: 760px)` 压缩检查器段距、字段高与提示留白，1040×680 下“恢复原比例”按钮不再被底部裁掉。

**验证**

## C03 多轮廓复合路径 + 共点分支 + 角点/平滑点（2026-11-24 23:23）

**为什么做**

**改法**

- `PathContour { anchors, closed }` 加进 `SceneNode.pathContours`；单轮廓仍只写旧 `pathAnchors/pathClosed`，多轮廓才写 `pathContours` 并镜像第一条，旧工程照常加载。
- `penContoursGeometry` 让多轮廓共享一个包围盒原点，`pathData` 每条轮廓拼一个 `M`；`pathContoursToWorld` 逐条还原世界坐标。`editor` 统一为 `commitPathContours/setPathContours`，`setPathAnchors` 只替换第一条并保留其他。
- `CanvasView` 的锚点引用从数字升级为 `{ contour, index }`：命中、拖锚点/手柄、线段插点、`Delete` 删点、选中态都按轮廓工作。钢笔下选中节点后，`Alt`+点空白追加一条轮廓，`Alt`+点已有锚点以同一坐标起一条分支，收尾后保持工具与选中。
- 渲染：Canvas 与 SVG 都按轮廓拆绘制，闭合轮廓才填充，开放轮廓固定 `fill="none"`、只吃描边；追加开放分支时若节点没有描边，自动补 2px `#221C00`，避免分支线不可见。

**为什么做**

## D03.1 图层效果 + B02.1 选中适配（2026-11-26）

**为什么做**

Figma 的图层效果是界面设计里最常用的“立体感”来源，Groma 右栏此前只有圆角/透明，投影和模糊完全没有；同时 `Shift+2` 一直误走全部适配，选中一个小图层时仍缩在整张画板。两个都是现有骨架内的补洞，不新增面板。

**改法**

- 数据加 `effects`，单节点可叠多条“投影 / 整层模糊”。投影字段 X/Y/模糊/颜色/透明度，模糊只有半径；每条有显示/隐藏与移除，添加到分组底部。

## C06.1 图片裁剪 + 粘贴图片 + 字距（2026-11-26）

**为什么做**

图片节点能导能换，但用户看不到裁剪入口；Figma 的图片双击进裁剪、框外压暗、拖角收放是高频操作。粘贴图片则是最短的一条“从别处拿图进画板”路径。字距是文本检查器里最明显缺的一个字段，先把基础样式补齐。

**改法**

- 图片裁剪不改节点位置/尺寸，只存 `imageCrop`：归一化 `{x,y,w,h}`，缺省全图，旧工程兼容；裁剪模式是瞬态 `cropId`，不写 scene、不持久化。
- 画布进入裁剪时该图片临时画整张源图；覆盖层用 SVG：框外四块暗色矩形压暗、1.5px 品牌色边框、三分网格、四个 8px 角点。框内拖动平移，四角收放，最小 2%；拖动只产生一条撤销。
- 右栏图片检查器新增“可见 59% × 39%”与四按钮：裁剪图片/退出裁剪、恢复原比例、替换图片、重置裁剪；裁剪中按钮点亮（`.wide-action.is-on`），底部提示改为裁剪操作。视觉继续用现有方角中性底与单一品牌黄。
- `Ctrl+V` 粘贴位图：焦点不在输入框时拦截，写入工程 `assets` 后按自然尺寸插到当前画板并选中；Toast 复用顶栏位置，显示文件名与尺寸。未保存工程给“先保存工程”提示，不产生幽灵资产。
- 字距：`letterSpacing` 单位 px，可负值；字号/字重/字距改为三列 `.field-grid.is-triple`，不新增一行。Canvas `ctx.letterSpacing` 与 SVG `letter-spacing` 同步。

**验证**

- 真实 EXE 裁剪：`image-crop.groma` 高原湖泊图片 1200×600，拖角 72%×55%→59%×39%，`Ctrl+Z` 回退，Esc 退出；截图 `shots/image-crop-max.png` 框外压暗可见左右恢复内容、右栏“退出裁剪”点亮。PNG 1,474,137 B、SVG 4,855,607 B，Chromium 渲染与 PNG 一致。
- 真实 EXE 粘贴：`粘贴图片验收.groma`，合成 480×320 PNG 粘贴事件，Toast“已粘贴图片 · paste-test.png · 480 × 320”，图层树出现图片行并选中；`scene.json` 与 `assets/paste-test.png` 147,882 B 落盘；截图 `shots/paste-image-max.png`。
- 真实 EXE 字距：`文字样式验收.groma` 标题 0→6，画布拉开、保存重开仍为 6、导出 SVG 含 `letter-spacing="6"`；截图 `shots/text-spacing-max.png`、`text-spacing-reload.png`、`text-spacing-export.png`。
- `npm run gate` PASS：27 文件 / 179 条，MCP selftest 通过；CSS 60.35 kB、JS 501.17 kB；EXE 3,301 KB，2026-11-26 13:29:18。

**边界**

- 裁剪命中仍按节点矩形，旋转图片的覆盖层未旋转；不做裁剪焦点/焦点定位。图片填充到形状、孤儿资产清理仍未做。
- 粘贴只接受 `image/*` 位图，SVG 文本仍在顶栏导入；工程必须先保存。
- 字距只作用于整段文本，不做富文本片段与 kerning 覆盖。

## C05.2 Alpha/亮度蒙版 + 多画板可见区（2026-11-26）

**为什么做**

几何蒙版只能硬裁轮廓，海报淡出、羽化窗口、图片透明度遮罩还做不了；同时真实工程常把几百个画板平铺在同一页，根循环每一帧仍要遍历全部画板。这一刀补 Alpha/亮度两种像素蒙版，并让中心画布只进入视口附近候选。

**改法**

- `SceneNode.maskType?: 'geometry' | 'alpha' | 'luminance'`，缺省 `geometry`，旧工程无需迁移；schema 校验枚举。
- `mask.ts` 新增 `maskTypeOf`；资格、唯一蒙版、上方兄弟、命中与几何路径继续复用。
- Canvas 新增 `drawPixelMaskedChildren`：把蒙版上方兄弟画进离屏层，蒙版单独画进 mask canvas；Alpha 用 `destination-in` 直接保留蒙版像素，亮度先用 `0.2126R + 0.7152G + 0.0722B` 乘原 alpha 转成 alpha，再合成；离屏层继承当前变换/全局 alpha，贴回主画布时恢复 identity，不破坏画板/区块裁剪。离屏 canvas 按容器深度复用，同一帧不反复分配整窗画布，嵌套蒙版各用独立槽位。
- SVG `emitChildren`：几何继续 `clipPath`；Alpha/亮度输出 `<mask maskUnits="userSpaceOnUse" mask-type="alpha|luminance" style="mask-type:...">` 与 `<g mask="url(#...)">`，导出坐标与画板原点一致。
- 右栏蒙版段新增“轮廓 / Alpha / 亮度”三段切换，默认轮廓；启用蒙版时写 `maskType: node.maskType ?? 'geometry'`，切换各一条 patch 历史。
- 根级画板空间索引：512 场景像素网格，单画板最多 64 格，超大画板进 oversized，查询最多 4096 格，视口外扩 48 屏幕像素；少于 24 个根节点或根上有蒙版退回原遍历。索引按 `x/y/w/h/rotation/visible/isMask` 轻量签名失效；旋转画板用四角 AABB，避免只登记原框。
- 索引只决定“进入哪些根画板”，画板内部仍由 `drawNode`/`intersects` 做逐层视口裁剪；z-order 保持原 `children` 顺序。

**验证**

- `mask.test.ts` 5 条：资格/唯一、点包含、命中过滤、几何 SVG clipPath、Alpha/亮度 SVG mask；`schema.test.ts` 16 条含非法 `maskType`；`render.bench.test.ts` 2 条含 600 画板索引与“移动画板后节点数下降 9”的失效断言。完整 `npm run gate` PASS：26 文件 / 173 条，MCP selftest 通过；CSS 60.20 kB、JS 493.41 kB；EXE 3,301 KB，2026-11-26 07:34:37。
- Alpha 真实窗口：`alpha-demo.groma`，椭圆蒙版从实心蓝渐变到透明，右栏 Alpha 点亮，提示“裁切上方 2 个图层”；截图 `shots/alpha-final-max.png`。导出 PNG `桌面 1440@1x-3.png` 1,440×900 / 50,442 B、SVG 1,421 B，`mask-type="alpha"`；Chromium 渲染 `shots/alpha-svg-render.png` 与 PNG 画面一致。
- 亮度真实窗口：`luma-demo.groma`，蒙版黑→白渐变，蓝色图层左淡右实，右栏亮度点亮；截图 `shots/luma-final-max.png`。PNG 113,855 B、SVG 1,372 B，`mask-type="luminance"`；`shots/luma-svg-render.png` 与 PNG 一致。
- 600 画板真实窗口：`Perf-600.groma` 600 画板 / 5,400 图层 / scene 1.6 MB；100% 缩放下只出现视口附近 4 块画板（画板 285/286/315/316），左栏 600 个画板行可滚动，页面检查器“600 个画板”；截图 `shots/many-frames-600.png`。基准 30 次平均 0.14ms，只画 57/5,399 节点。
- 自检：Alpha 首版截图全白，定位为验收 fixture 把渐变端点写成 0–1 归一化，而 Groma 的线性渐变用图层本地绝对坐标；改为 0→500 后 Alpha 与亮度都恢复，未改产品代码。

**边界**

- Alpha/亮度蒙版用整窗离屏 canvas，多个大蒙版会放大内存与合成成本；后续按可视包围盒裁小。
- 命中仍只按几何轮廓，不读取 Alpha/亮度像素；点到淡出区域仍可能选中被裁图层。
- 不做蒙版组、多个蒙版串联、羽化/扩展、跨父级提升；文本/图片不能直接作为蒙版。
- 索引只作用于根级画板；非裁剪容器子图层大量越出自身边界时，候选仍用容器外接框。图层面板仍非虚拟滚动，600 个顶层行会全部建 DOM。

## C05 几何形状蒙版（2026-11-25）

**为什么做**

C04 收口后，Figma 免费版还缺“把形状当蒙版裁掉上方图层”的基础能力。没有它，图片裁切、异形窗口和海报遮罩只能靠导出到外部软件。这一刀只做几何蒙版，保持对象模型简单：一个普通图层打 `isMask`，同容器上方兄弟被它裁切。

**改法**

- 数据只加一个 `isMask?: boolean`，旧工程不需要迁移；`schema` 校验布尔类型、父级、类型与无子图层。删除上层后留下的惰性蒙版允许保存/重开（渲染为空裁切），避免正常编辑把工程写成不可打开。
- `src/core/mask.ts` 统一资格与几何：`maskEligibility` 给 UI 原因，`maskIndexForParent` 找最上面的可见蒙版，`pointInMask` 按 `evenodd` 判定点是否在轮廓内（含内孔）。
- 画布 `drawChildren` 变成所有容器的唯一子图层循环：先画蒙版下方，再用世界 rings 建 `Path2D` 裁切，最后画上方；蒙版自身不绘制。
- SVG 用 `clipPath + path fill-rule="evenodd"` 包住上方兄弟；画板 PNG/JPG、切片 PNG/JPG 与组合图层 PNG 也统一走 canvas 蒙版路径。这里修过一个真实问题：首版 PNG 画板导出仍用旧 child 循环，导出图没有蒙版；改为 `drawChildren` 并给 `clipToMask` 补 `ox/oy` 坐标偏移后，PNG 与画布、SVG 一致。
- 命中测试 `walkHit` 在蒙版外跳过被裁切的上方兄弟，蒙版自身仍可通过图层树或空白蒙版区域选中；右侧检查器新增“蒙版”分组，启用时按钮变“取消蒙版”并显示“裁切上方 N 个图层”；图层行加“蒙版”小标签。
- 启用/取消都走 `editor.applyPatch`，各产生一条历史，不新造命令类型；隐藏蒙版不裁切，锁定蒙版仍裁切。

**验证**

- `mask.test.ts` 4 条：资格/唯一性、矩形与椭圆点包含、命中过滤、SVG clipPath；完整测试 26 文件 / 171 条通过；完整 `npm run gate` PASS，MCP selftest 通过，CSS 60.16 kB、JS 488.56 kB、EXE 3,300 KB（2026-11-25 21:01:54）。
- 真实 EXE `mask-demo.groma`：椭圆蒙版裁切“蓝色大图层 + 蒙版内文字”，右栏“用作蒙版” → 图层出现“蒙版”、提示“裁切上方 2 个图层”；`Ctrl+Z` 回到未蒙版，重做恢复。
- 三档 UI：`shots/mask-final-max.png`（1707 CSS，右栏完整）、`mask-1440.png`（946 CSS，蒙版标签与按钮可见）、`mask-1040.png`（679 CSS，按钮仍可见）。1040 下右栏信息多，蒙版提示位于滚动区底部，属于既有检查器滚动行为。
- 导出：`桌面 1440.svg` 1,713 B，含 `groma-mask-1`、`fill-rule="evenodd"`，浏览器渲染为椭圆窗口；`桌面 1440@1x-2.png` 与 SVG 画面一致。首版 PNG 未裁切的问题已在同一刀修复并复验。

**边界**

- 本刀当时只有几何蒙版：不读取蒙版填充的透明度；Alpha/亮度、羽化、扩展、蒙版组与多个蒙版串联已在 C05.2 补了一部分（仍不做羽化/组）。
- 文本/图片不能直接当蒙版；跨父级不提升。蒙版仍是普通图层，可移动/缩放/改圆角，但不参与布尔运算。
