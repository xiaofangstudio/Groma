# Groma 开发约定（对 AI / 协作方）

> 本文件与 `README.md` 的规格同等效力，属于硬约定，不做「视情况而定」。

## 一 交付与验收：每回做完都要截图

1. **每次做完**（里程碑、界面改动、任何能跑起来的产物）都要开虚拟桌面、截图发给用户；用户经常不在电脑前，看不到窗口等于没交付。
2. **截完立刻关**，不管接下来还要不要用。这台机器上跑着远程桌面，虚拟桌面留一个就会撞上，用户会没法用电脑。要再用就重新开，不做复用、不做并行，一次只开一个。
3. 只截应用窗口，不截整个桌面：走 `tools/shot.ps1`（`PrintWindow` 抓窗口位图，窗口被挡、用户不在前台也能出图），脚本在 M0b 建窗口时一并建好。
4. **截图先自检，再发**：截完先自己看画面、裁切、溢出、旧 Toast、路径与焦点；发现问题先修、重截，确认无问题才发，不把“刚截的原图”直接丢给用户。
5. 截图存 `shots/<日期>-<说明>.png`，随交付一起给；不许拿截图当摆设，结论要写在文字里。
6. 验收完把测试进程清干净（`Get-Process groma`），不留后台窗口干扰下一次。

## 二 MCP

- Groma **必须自带 MCP**：`mcp/` 目录，stdio 服务；当前已落地 9 个工具，清单见 README 4.7。
- 当前 `mcp/lib/store.mjs` 独立实现读写与树操作，字段与 TS `GromaDoc` 对齐，并带独立的结构校验（父子互指、重复归属、环、孤儿）；**合并 `src/core` 构建产物 `mcp/lib/core.gen.mjs` 仍是待办**，在完成前不要对外宣称“共用同一份解析”。
- 写操作默认 `dryRun=true`，显式 `false` 才落盘，落盘前自动快照。
- MCP 不承担渲染热路径，也不代替应用内撤销栈。

## 三 开工顺序与验收门槛

- 顺序：**M0a 数据层 → M0b 界面骨架 → M1 垂直切片**（矩形 → 选择 → 拖动 → 属性面板 → 图层树 → 存盘 → 导出 PNG）。
- M0a 的实现口径以 `docs/地基规格.md` 为唯一依据，单测逐条对应 0.5 表。
- 每步必须过 `npm run build` 与 `npm test`，不过不往下走，不拿「先记着」糊过去。
- `npm run bench` 已落地 5000 节点基准：命中首节点约 0.1–0.3ms、复制 2000 节点约 4ms、200 步撤销约 0.3–0.6s、全树 JSON 字符串化约 8–9ms、结构校验约 30ms、100 次写-读-写往返零不一致。它是数据层基准，不等于真实画布 60fps。
- 场景变更已统一走 `src/core/commands.ts` 的 `applyCommand`；`addNode / deleteSelected / duplicateSelected / updateSilent / nudgeSelected / 事务回滚` 均不再直接改树。新增写操作前先加命令与单测，禁止在 UI 里直接改 `doc.nodes`。

## 四 本机资源

- 本机同时在编译音游时**不跑 `cargo build`**：先做 TS 层，用 `npm run dev` 浏览器预览验证，等机器空下来再编 Rust。
- Rust 只做慢路径（zip、PNG 编码、字体枚举、缩略图）；任何热路径逻辑进 Rust 一律驳回。

## 五 红线复述

零 AI、零账号、零云、零网络端口；不引组件库；不抄 GPL；场景图只在 TS；黄只点缀不铺底；MCP 只做本地 stdio。

## 六 交付纪律（Reelix 的账单，README 第零章为权威）

- **交付 = 双击打开的那份 exe**。源码写完、`npm run dev` 能看，都不算交付。
- 交付前三查：`dist/**` 与 exe 时间戳都晚于最后一次源码改动；没有残留进程占着旧 exe；快捷方式指向这次新编的包。
- `npm run gate` 当前实际检查：`vitest`（含 5000 节点基准）→ 前端构建 → MCP 自检 → 编 EXE → exe 时间晚于源码。**三档视口溢出、真实画布帧率、残留进程尚未进 gate**，别把没做的检查写成已过。
- 假功能三不：不注册没实现的工具、不弹「稍后开放」、不返回假路径/不装成功。发现一条即返工。
- 每个功能按 README 0.2 五条验收：有入口、有结果、能撤销、能存住、有截图。
- 截图脚本 `tools/shot.ps1` 支持 `-Open` / `-Welcome` / `-Click` / `-Click2` / `-ShiftClick` / `-Drag` / `-HoldDrag` / `-Enter` / `-PostWaitMs`；`-HoldDrag` 在鼠标按下时截图，专门截拖动中的参考线、框选框等瞬时状态。输入投递到 `Chrome_RenderWidgetHostHWND`，每次 `finally` 关闭虚拟桌面。需要先操作弹窗再截图时，用 `-CdpScript <path> -CdpPort <port>` 在虚拟桌面应用启动后跑 Node CDP 脚本；脚本必须校验 target title，不能盲取 `targets[0]`。

## 七 布局纪律

- 面板与列表按 README 6.14 的十条硬规矩做：`min-width: 0`、单行截断、字段最小宽、行高下限、屏内控件预算。
- 细节、动效与投产条件按 `docs/界面典范与细节.md` 走：Strata 的克制时长、Scheda 的窗口规矩、Chapter 的欢迎页叙事。
- 任何新增面板先在 1024×680 与 125% DPI 下过一遍；放不下就折叠或换行，不许靠加宽窗口解决。
