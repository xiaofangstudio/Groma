## 零 工程铁律（优先级最高，与后文冲突时以本章为准）

> 这一章是 Reelix 用一条产品线换来的。它列了 42 个效果、28 个 MCP 工具，最后被弃用——不是功能少，是**用户双击打开的那一份不能用**。Groma 的难度不低于它，所以先把这一章立在所有功能之前。

### 0.1 Reelix 的四条死法（每条都对应本项目的防呆）

| 死法 | 当时的现场 | Groma 的防呆 |
| --- | --- | --- |
| 交付了旧壳 | 用户点的是 13:10 编的 exe，源码改到 16:44；探测发现包里 `invoke` 出现 0 次——前端根本没接后端 | 交付只认「双击打开的那份」，时间戳 / 快捷方式 / 实测截图三查（0.3） |
| 假按钮 | 「导出」点了弹「将在 M4 开放」；缩略图函数只返回一个预期路径、文件没生成；蒙版节点注册了、调度里是空壳 | 三不：不注册没实现、不弹稍后开放、不返回假路径（0.4） |
| 依赖没随包 | COLMAP 339MB、FFmpeg 154MB 漏传，别人下载后功能是灰的 | 运行时依赖随包或启动探测，缺什么、怎么补要说清（0.7） |
| 架构返工 | 单编辑器 + 底部页签做到一半才被要求改四页，整块重组，前面的面板全返工 | 界面骨架一次定型，地基不绿不许盖楼（0.5） |

### 0.2 什么叫「能用」（五条，缺一不算做完）

任何功能必须同时满足，才算存在；少一条就是没做：

1. **有入口**：工具栏 / 菜单 / 快捷键能点到，入口不是灰的摆设。
2. **有结果**：点了有可见、可验证的产出（画出来、存下来、导出去）。
3. **能撤销**：误操作 `Ctrl+Z` 能回去，且只退一步。
4. **能存住**：保存 → 关窗 → 重开，内容一致。
5. **有截图**：交付时附实测截图；「应该可以」不算。

### 0.3 交付对象只有一个：双击打开的那份

- 验收对象是 `src-tauri\target\release\groma.exe` 和 NSIS 装出来的那份，**不是源码，不是 `npm run dev` 的浏览器**。
- 每次交付前三查：① `dist/**` 与 exe 的写入时间都晚于最后一次源码改动；② 没有残留进程占着旧 exe；③ 桌面/开始菜单快捷方式指向这次新编的 exe。
- Tauri 打包必须带 `custom-protocol`；不带会编成连 `localhost` 的 dev 壳，双击是白屏或「拒绝连接」。
- 关窗后进程必须归零，任务管理器里不留 `groma`。

### 0.4 三不（发现一条即返工）

1. **不注册没实现的工具**：工具栏有图标、菜单有项、MCP 有工具，就必须真能跑。
2. **不弹「稍后开放」**：没做的功能不出现在界面上，宁缺勿假。
3. **不返回假路径、不装成功**：文件没生成就不许返回路径；保存失败就不许显示「已保存」。

### 0.5 地基 C100（M0 必须全绿，才允许盖第一层楼）

| 地基 | 判定标准（实测，不是读代码） |
| --- | --- |
| 坐标与变换 | 2%–6400% 缩放往返 100 次回到 100%，元素位置偏差 ≤ 0.5px；旋转/翻转后命中误差 ≤ 1px |
| 场景图 | 编辑器写路径统一走 `src/core/commands.ts` 的 `applyCommand`；直接改树的旧 helper 已删除（事务回滚也走 `patch`） |
| 撤销 | 200 步连续撤销后与初始树深比对完全一致；单步 ≤ 50ms（5000 节点最坏情形） |
| 序列化 | 「读→写→读」100 次规范化 JSON 字节级一致；旧字段缺省有默认值，不崩 |
| 命中测试 | 5000 节点单击命中 ≤ 1ms；旋转、缩放、嵌套容器内坐标准确 |
| 渲染 | 5000 节点平移缩放 60fps；拖拽时只重画覆盖层，不整树重绘 |
| 自动保存 | 停手 1.4s 内落盘；输入期间可感知卡顿 ≤ 100ms；杀进程后重开 0 丢失 |
| 异常 | 任意错误路径都有中文提示（哪里错 + 怎么办），不白屏、不吞异常 |

这张表就是「地球内部灌 C100」：**任何一行不绿，不往上加功能**。落地细则（场景图不变量、撤销补丁、渲染分层、原子写、测试矩阵）见 `docs/地基规格.md`；`npm run gate` 一键体检（时间戳、测试、基准、残留进程），不过不许交付。

### 0.6 只做垂直切片，不横铺面板

- 每个阶段只交付**一条从头走到尾走通的链路**，走通再开下一条。
- 第一条：矩形 → 选择 → 拖动 → 属性面板改尺寸 → 图层树 → 保存 → 重开还在 → 导出 PNG → `Ctrl+Z` 回退。
- 禁止「五个面板各做一半」：半成品不给用户看，等于零。

### 0.7 依赖与能力探测

- 运行时依赖（WebView2、系统字体、编码器）必须随包，或启动时探测；缺了给中文提示「缺什么、怎么补」，不许静默失败。
- 每台机器能力不同：导出前探测可用编码器与字体，不可用自动降级并告知，不假装成功。

### 0.8 每次交付长什么样

1. 一句话结论：这次做完了什么、还差什么。
2. 实测截图（应用窗口，不是整张桌面）。
3. 验收清单逐条打勾（对应 0.2 五条）。
4. 下一刀切哪里。

## 一 定位

### 1.0 对标原则（硬约束）

1. **基线不是“够用”**：Figma 免费版能做的，Groma 必须逐项做齐；没做的进能力矩阵，不能拿“小切片”当完整度。
2. **融合不是堆功能**：Figma 做不到、但其他工具已验证能服务界面设计工作流的（本地优先、代码 / MCP、AI 辅助、离线可用等），作为差异化能力纳入。
3. **每一刀落在矩阵的一行**：真实入口、可保存、可撤销、可恢复、真实窗口验收；不放假按钮，不抄 Figma 的品牌、素材和私有实现。

**执行版矩阵**：`docs/Figma能力矩阵.md`（状态图例、基线 / 融合矩阵、刀序、反 Reelix 红线、每刀开工单与完成判定）。`docs/Figma功能蒸馏参考.md` 是全量底本，不直接当开工单。

一句话：**给做界面的人用的矢量设计工作台——画板、约束、自动布局、组件系统，全在一处，本地存档，离线可用。**

和家族里另外两个画图产品分工清楚：

| 产品 | 管什么 |
| --- | --- |
| **Strata** | 位图：照片修图、笔刷绘画 |
| **Vecora** | 矢量插画与印刷排版：插画、海报、印前 |
| **Groma** | **界面**：画板 Frame、约束 Constraints、自动布局、组件/变体、设计变量、原型、Dev Mode 交付 |

这三样（画板体系、约束、自动布局+组件）是 Vecora 没有的，互不抢地盘。Groma 的矢量引擎服务于界面，不追求印刷级路径高级排版。

**明确不做的（红线，v1.0 一律不进）**：

| 不做 | 原因 / 归谁 |
| --- | --- |
| 一切 AI 能力 | 工作室全线红线 |
| 账号、云端、实时多人、评论系统 | 单机红线；局域网无账号协作列远期，不排期 |
| FigJam 白板 | 不单独立项，Groma 也不做「草稿页」模式，保持窄 |
| Slides / Sites / Buzz | Lanterna、网页发布、品牌库各归各 |
| 社区与插件市场 | 插件只做本地加载（四期） |
| 三维、视频 | 不在产品线 |
| 位图编辑（笔刷、修图） | Strata 的活；Groma 的图片只是填充与资产 |

## 四 技术路线

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 外壳 | Tauri 2 | 与全家一致，系统 WebView2，安装包小 |
| 界面 | React 19 + TypeScript + Vite | 沿用 Strata 确立的设计令牌与排版规范 |
| 场景图与渲染 | **TS 层（WebView 内）** | 场景树、Canvas2D 渲染、命中测试、撤销栈全在 TS：画布热路径（每帧渲染/拖拽命中）不能跨 IPC |
| 核心 | Rust（groma-core） | 只做慢路径：`.groma` zip 打开保存、PNG/JPG 编码写盘、文件校验、会话恢复；**不碰场景图** |
| 渲染器 | Canvas2D 起步 | 命中测试用几何算法（逆矩阵+包围盒），不用 getImageData；性能撞红线再迁 WebGL，不提前 |
| Auto Layout（二期） | 自写 flexbox 子集 | 只做水平/垂直 + Hug/Fill/Fixed 三态，够用即可，不引第三方布局库 |

### 4.1 坐标与精度

- 场景一律 f64 逻辑坐标，y 向下，单位 px（1x 导出即逻辑像素）
- 渲染时按缩放比换算并做 0.5px 对齐（1px 线条不糊）
- 命中测试走节点逆变换矩阵，点先转局部坐标再判形状

### 4.2 撤销栈

- 命令模式：每次变更生成反向补丁（属性级 diff，不是整树快照），内存可控
- 面板拖滑杆合并为一步（停手 300ms 视为一次提交）
- 撤销上限 200 步，超出丢弃最旧

### 4.3 导出实现口径

- PNG/JPG：一期用 WebView 离屏 Canvas 光栅化（`toBlob`），零 IPC 大包；单张超过 4096px 或批量超过 20 张时再走 Rust 侧（groma-core）光栅化
- SVG：场景树直接序列化（渐变/虚线/文本转路径口径在实现时按 Figma 行为对齐）
- Copy as CSS：只生成布局与视觉摘要（尺寸/圆角/填充/阴影），不追求逐像素

### 4.4 保存策略（与 Chapter 同口径）

停手 1.4 秒自动保存 + 30 秒兜底；失焦、切页、切换工具组大类、导出、关窗强制存盘。顶栏「未保存 / 保存中 / 已保存」三态反馈，保存失败弹提示不装成功。每次打开工程生成一个版本快照，保留最近 20 个；另有崩溃恢复：异常退出后下次启动提供「恢复上次会话」。

### 4.5 底层是 Rust（groma-core）

产品的心脏是 Rust：界面跑在 WebView 里，**所有碰磁盘、碰编码、碰系统的事都由 Rust 做**，界面只拿结果。

| Rust 负责 | 具体内容 | 用到的 crate |
| --- | --- | --- |
| 工程读写 | `.groma` 目录打包/解包、版本校验、字段迁移 | `zip` `serde` `serde_json` |
| 资产 | 图片读入、内容哈希去重、写盘、格式嗅探 | `sha2` `image` |
| 导出光栅 | 超过 4096px 或批量 > 20 张时的离屏光栅化与编码 | `image` `resvg`（可选） |
| 缩略图 | 欢迎页卡片与页签缩略图生成、缓存清理 | `image` |
| 系统 | 字体枚举、最近工程列表、文件监听、回收站移动 | `font-kit` `notify` `trash` |
| 恢复 | 崩溃会话标记、自动备份、快照轮转 | — |

**为什么是 Rust**：单二进制无运行时依赖、内存安全、并发好写（`rayon` 切分批量导出）、与家族所有软件同一底座；zip / 图像编码 / JSON 生态成熟，不用自己造轮子。

**线程模型**：Tauri 命令默认异步跑在 tokio；重活（批量导出、缩略图重建）走 `spawn_blocking`，进度用 event 增量回传，界面不卡。

**命令清单（一期）**：

```
project_open / project_save / project_list / project_delete
asset_import / asset_hash / export_raster / thumbnail_build
font_list / recent_list / session_recover / snapshot_create / snapshot_restore
```

**红线**：场景图、命中测试、布局计算、撤销栈**一律不进 Rust**——这些是全在 TS 层跑的热路径，跨 IPC 会直接掉帧。Rust 只做「一次调用、一次返回」的慢活。

### 4.7 MCP 接口（全家族必备，一期随 M1 同批落地）

小方工作室每款软件都带 MCP，Groma 不例外。它是本机 stdio 服务：外部 MCP 客户端（Claude Desktop、Cursor、任意客户端）**不开界面**就能读写 `.groma` 工程。MCP 是外部接口，不是应用内 AI，红线不变。

| 项 | 口径 |
| --- | --- |
| 位置 | 仓库根 `mcp/`，入口 `groma-mcp.mjs` |
| 传输 | stdio，零监听端口 |
| 协议与依赖 | MCP `2024-11-05`；`@modelcontextprotocol/sdk` + `zod` |
| 沙箱 | 环境变量 `GROMA_MCP_ROOT`，设了则所有路径必须落在其内，越权直接拒绝 |
| 存储复用 | 当前 `mcp/lib/store.mjs` 独立实现读写、快照与树操作，字段约定与 TS `GromaDoc` 对齐；后续合并为同一份 `mcp/lib/core.gen.mjs`，禁止长期双份逻辑 |
| 写盘保护 | 任何写操作默认 `dryRun=true`，显式传 `false` 才落盘；落盘前自动建快照 |

## 五 文件格式

工程是一个目录，后缀 `.groma`（照 Chapter / Float 工程包习惯）：

```
我的设计.groma/
  project.json        版本号、工程名、作者、页清单、创建/修改时间
  scene.json          全部页的场景树（含 v1 手动参考线 Page.guides）
  pages/
    <页 id>.meta.json  后续拆分预留（布局网格、页面备注）；参考线 v1 暂不拆出
  assets/             图片资产（按内容哈希命名去重）
  snapshots/          最近 20 个版本快照
```

**scene.json 节点模型**（v1 字段，只加不改）：

```
公共：id · type · name · parentId · childOrder
几何：x y w h · rotation · flipH flipV · opacity · visible · locked
画板：framePreset · clipContent · constraints { h: left|right|center|scale, v: top|bottom|center|scale }
外观：fills[] · strokes[] · effects[] · blendMode · cornerRadius（四角可分）
文本：content(runs) · fontId · fontSize · lineHeight · letterSpacing · textAlign · autoWidth
路径：vectorData（子路径+锚点+手柄，closed 标记）
布尔：boolOp（union|subtract|intersect|exclude）
导出：exportSettings[]（格式/倍率/后缀）
```

- 纯文本 JSON 可读，坏了能用记事本救；图片是明文 PNG/JPG 文件
- 整个 `.groma` 目录拷走即迁移；删除工程先移入 `<书库>/../.回收站/`（与 Chapter 同规则）
- 版本兼容：`project.json.version` 只加字段不改语义，旧文件永远可开

## 六 设计规范（与家族统一，写死）

### 6.1 外观基调

延续 Strata Relax：**白底为主 + 品牌色点缀、极度扁平、无重阴影无强渐变**，品牌色黄。全部只引用令牌，不写死颜色。

### 6.2 主题令牌（浅色定稿，v1 只有浅色）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#f8f7f4` | 窗口底 |

| `--surface-2` | `#f1efe9` | 次级面、输入底 |
| `--border` | `#e4e1d8` | 分隔线 |
| `--canvas-bg` | `#e9e8e4` | 画布区底（中性，不抢内容） |
| `--text` | `#221c00` | 墨字正文 |
| `--text-2` | `#6d685e` | 次要文字 |
| `--text-3` | `#a19b8e` | 提示文字 |
| `--accent` | `#f2b705` | 主黄：选中描边、Logo、焦点 |
| `--accent-bright` | `#ffd43b` | 悬停态点缀 |

**黄色用法边界（已定）**：黄色只做点缀与状态（选中描边、焦点、高亮、Logo），**主操作按钮一律墨底 `#221c00` 白字 + 黄色点缀**（图标或左侧短条），黄色大面积铺底可读性差，永不用于按钮底色。选中框：主黄 1.5px 描边 + 白底黄边四角手柄。

### 6.3 圆角、间距、字号

- 圆角：`--r-xs` 6 / `--r-sm` 8 / `--r-md` 12 / `--r-lg` 16 / `--r-full` 999
- 间距一律 4 的倍数（4/8/12/16/24/32/48/64）；字号 11 / 12 / 13 / 14 / 16 / 20 / 26
- 界面字体：系统栈（Segoe UI / 微软雅黑 / PingFang SC）；画布文本用系统已装字体，一期不内置字体文件

### 6.4 磨砂玻璃（真玻璃，不是糊一层）

**用在哪**：顶栏、左右面板边框、下拉菜单、弹窗、Toast、Tooltip、欢迎页卡片。
**不用在**：画布区（永远中性实底）、属性面板正文区（长时间注视，实底更稳）。

参数（浅色）：

```css
background: rgba(255, 255, 255, 0.62);
backdrop-filter: blur(22px) saturate(1.6) brightness(1.03);
border: 1px solid rgba(255, 255, 255, 0.55);
box-shadow:
  inset 0 1px 0 rgba(255, 255, 255, 0.6),
  0 12px 32px rgba(34, 28, 0, 0.10);
```

- **噪点**：叠一层内联 SVG `feTurbulence`（`baseFrequency=".8" numOctaves="3"`），`opacity: .035`，`mix-blend-mode: overlay`，给玻璃磨砂颗粒感
- **必须透得出东西**：窗口底铺两团极淡黄光晕（`radial-gradient`，`rgba(242,183,5,.10)` 与 `rgba(255,212,59,.08)`），否则玻璃在纯白底上会显得发灰
- 玻璃卡本体**禁止** `clip-path`，会切断 `backdrop-filter` 采样
- 透明度 / 磨砂 / 饱和 / 光泽四个参数进偏好设置，所见即所得

### 6.11 深色模式

### 6.12 动效

- 三档：完整 / 精简 / 关，跟随系统「减少动效」降级；关档统一归零（`scroll-behavior:auto`，过渡 1ms）
- 时长口径：反馈 90–120ms、入场 180–220ms、退场 120–150ms、大面板 280ms；`--ease-out` 主用，`--ease` 交互，`--ease-spring` 只给「按下」与小弹层
- 弹性只用于用户主动按下的反馈，不用于被动出现的内容（Strata 口径）
- 全应用只允许一处氛围动画：启动页 ≤800ms 淡出。Chapter 的 600ms 入场、26s 呼吸、卡片流光不搬进编辑器
- 必做清单：启动页淡出、欢迎页卡片浮入、面板折叠展开、图层树展开收起、属性面板滑入、下拉菜单弹出（缩放 0.96→1 + 淡入）、弹窗进出、Toast 上滑、缩放动画（`Shift+1/2`）、小地图淡入、保存状态三态切换
- 画布拖拽缩放本身**不加**动画（跟手优先）；精简档只去位移与弹性，保留淡入

### 6.13 Section 区块与画布辅助（视觉与参数）

**Section 在图层树中**

- 容器节点，与 Frame 同级，行高 28；内层 Frame 每级缩进 14px
- 图标 16×16：**虚线圆角方框**（Frame 是实线方框），同为主黄描边
- 名称默认「区块 1」，双击重命名；左侧三角可折叠，默认展开
- 行背景极淡黄 `rgba(242,183,5,.06)`，hover `.10`，选中时左 2px 黄条
- 选中 Section 时属性面板显示：名称、位置尺寸、背景色、背景模糊、网格排列开关、裁剪内容
- 导出：Section 本身不渲染，子节点照常导出；勾选「连区块一起导出」则按区块边界裁切输出

**Section 在画布上**

- 无填充，1px 虚线框 `rgba(34,28,0,.18)`（dash 4 3），四角各一个 6×6 小把手
- 标题在框外上方 8px，13px `--text-2`；缩放低于 40% 时标题隐藏
- 折叠时只留标题胶囊：高 22、`--r-full`、白底 + 1px 描边，点击展开
- hover 时虚线变主黄 1px 实线

**画布缩略图**

- 卡片内尺寸 200×125（16:10），页签 24×15
- 生成：离屏 Canvas 按内容包围盒等比缩放，最大输出 400×250 png
- 缓存：`<工程>/thumbnails/<页id>.png`，内容变更后 2 秒防抖重建
- 空白页面用占位图：中性底 + 淡网格 + 中央淡色 Logo

**小地图（Minimap）**

- 位置：画布左下角，距边 16px；宽 180，高按页面比例，限制 60–120
- 外观：`--r-sm`、白底 88% 不透明、1px 描边；画板缩为淡灰块 `rgba(34,28,0,.12)`
- 视口框：1.5px 主黄描边、无填充；拖拽框平移，点击空白处跳转居中
- 滚轮不在小地图上响应（避免误缩放）；内容包围盒小于视口的 1.5 倍时自动隐藏，`Shift+M` 手动切换
- 进出淡入淡出 180ms

### 6.14 布局与密度（照 Strata / Scheda / Chapter 的实测口径，不许溢出）

> 三款被认定「UI 最好看、能当主力」的软件，共同点不是元素少，是**行高给足、单行截断、容器可收缩、分组能折叠**。Reelix 的拥挤来自反面：42 个效果、35 个面板往一屏塞，没有最小宽、没有截断，结果到处溢出。Groma 一条都不许复现。

**实测基准（从各自源码量的，不是估的）**

| 项 | Strata | Scheda | Chapter | Groma 取法 |
| --- | --- | --- | --- | --- |
| 顶栏 | 36 | 54（标题栏） | 44 | 40 |
| 左栏 | 工具轨约 48 | 无固定栏（阅读器） | 264 | 240 / 216 |
| 右栏 | 326（窗口 <1180 收 290） | 设置页卡片内边距 18–22 | 320 / 372 | 300 / 260 |
| 列表行高 | 28–31 | 46 | 30–34 | 图层 28、属性 30 |
| 控件高 | 34 / 40 | 32 药丸 | 32 / 38 | 图标 28、输入 34 |
| 状态栏 | 24 | — | — | 26 |
| 字号 | 12–34 | 9.5–25 | 12–34 | 11（元数据）12/13/14/16/20/26 |
| 文本溢出 | `min-width:0` + ellipsis | 单行截断 | 多处 ellipsis | 全部单行截断 |
| 节奏 | 4 的倍数 | 18/22 大留白 | 4 的倍数 | 4 的倍数 |

**十条硬规矩（逐条验收）**

1. 所有 flex / grid 子项统一带 `min-width: 0; min-height: 0`；不许拿 `overflow: visible` 兜底。
2. 单行文本一律 `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`，全名放 `title` 提示；禁止换行把行高撑破。
3. 面板正文不许出现横向滚动条。允许横向滚动的只有三处：代码块、表格、原型时间线（三期）。
4. 字段最小宽：数字 64、颜色 72、下拉 96、图标按钮 24。一行放不下就换到下一行（两行式），不许把字段压扁。
5. 高度下限：图层行 28、属性行 30、按钮 28、主按钮 34；低于这个值算不合格。
6. 间距只用 4 的倍数；面板内边距 12、分组间距 16、组内 4/8。禁止用 2px/3px 微调凑数。
7. 字号下限 11（只给元数据与快捷键提示），正文 12/13；禁止 10px 及以下。
8. 一屏控件预算：右栏同屏可见的可交互控件 ≤ 22 个；超出必须折叠或分页。五段默认只展开「对齐变换」，其余折叠。
9. 窗口最小 1024×680，三档宽度见 2.1；125% / 150% DPI 下按 CSS px 排版，不缩放字号。
10. 溢出必须能被发现：dev 模式 `Ctrl+Alt+O` 把所有 `scrollWidth > clientWidth` 或越出父容器的元素描红并列清单；交付前 `npm run overflow` 扫 1024×680 / 1280×800 / 1920×1080 三个视口，零命中才算过。

**右栏属性行模板（写死，不许自由发挥）**

```
[面板内边距 12]
[标签 72][字段 1fr，最小 64][单位 20][图标 24]     行高 30
放不下时：标签独占一行 18，字段下一行占满
[分组标题 36：13px/600 + 右侧折叠箭头]
[分组间距 16]
```

**为什么不是「把面板加宽就完事」**：加宽只解决 10%，剩下 90% 靠行高节奏、单行截断、字段换行、分组折叠。三款主力软件的右侧面板都比 Groma 原稿宽，但它们的行高和留白也更舍得给——宽度和呼吸感是一起给的，只给一样都还是挤。

### 6.15 三款主力的典范（细节、动效与投产条件）

三款能当主力的软件（Strata / Scheda / Chapter）的完整拆解见 `docs/界面典范与细节.md`；本轮欢迎页与令牌落地、三档实拍与 EXE 指纹见 `docs/UI家族化改版记录.md`。写进规范的要点：
- **性格不同，口径不同**：Strata 是冷工具（信息密度高但有秩序）、Scheda 是阅读器（留白优先）、Chapter 是内容型（氛围服务写作）。Groma 跟 Strata 的克制，欢迎页借 Chapter 的叙事，不借它的时长。
- **必抄**：单行截断、面板折叠成 36px 图钉条、36px 分组标题、数字输入可拖可滚可直填、状态栏只读、Toast 深墨底、窗口规矩、设置整页、光标/滚动记忆、文件关联。
- **不抄**：Chapter 的 600ms 入场 / 26s 呼吸 / 卡片流光；Scheda 的 1.75 行高；Strata 的 24 工具轨（Groma 一期 11 个够）。
- **投产十条件**：真实文件管线、自动保存与恢复、导出闭环、设置持久化、体积与性能守得住、零假功能 + 测试、错误可见、窗口细节、可发现性、语言与排版。十条缺一条，就只能算「能演示」，不算「能当主力」。

## 九 构建与运行

```bash
cd D:\20533\deskbox\fangwork\Groma
npm install

npm run dev          # 前端浏览器预览（无 Tauri，不落盘）
npm run tauri:dev    # 桌面窗口（开发）
npm run build        # tsc --noEmit + vite build
npm test             # 当前 12 个文件、55 条单测 / 基准

npm run bench        # 5000 节点：命中 / 撤销 200 步 / 序列化 / 子树复制
npm run gate         # 交付体检：单测（含基准）→ 前端 → MCP 自检 → 编 EXE → 校验 exe 新于源码
npm run mcp          # 启动 stdio MCP 服务
npm run mcp:check    # MCP 往返自检

npx tauri build --no-bundle   # 只出 groma.exe，不装 NSIS
npx tauri build              # NSIS 安装包（发布时）
```

- 可执行：`src-tauri\target\release\groma.exe`；安装包：`...\bundle\nsis\Groma_<版本>_x64-setup.exe`
- 截图：`pwsh -NoProfile -File .\tools\shot.ps1 -Out shots\x.png -Open "<工程 id>"`；支持 `-Click` / `-Click2` / `-ShiftClick` / `-Drag` / `-HoldDrag` / `-Enter`；`-HoldDrag` 保持鼠标按下，用于截取拖动中的参考线。
- `npm run gate` 已包含 5000 节点基准（跑在 `npm test` 里），但尚未包含三视口溢出扫描与残留进程检查；`npm run overflow` 还是规划项，别在交付说明里写“已过”
- TS 测试：`npm test`；Rust 侧当前没有独立单测，`cargo test` 只跑编译与内置测试（未来补 zip / 快照往返）
